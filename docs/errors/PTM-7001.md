# PTM-7001: object-missing

```text
✗ data/4f/4f2a…: pack is missing; 31 indexed chunks are lost
→ restore the object from a copy of the repository, or run a new backup; see docs/errors/PTM-7001
```

Other forms name a snapshot whose chunks are not in the index, or a chunk-list block that is not indexed.

## Cause

`pentym check` found that an object the repository relies on does not exist: a pack the index lists, or the index entries a snapshot's chunks need. Typical causes are objects deleted outside pentym, a bucket lifecycle rule that expired them, an incomplete copy of the repository, or an index file that was lost.

## Impact

Snapshots that use the missing data cannot be fully restored. Other snapshots are not affected.

## Fix

1. If the message names a snapshot's chunks and not a pack, the packs may still be there with their index lost: run `pentym repo rebuild-index`, then `pentym check` again.
2. If a pack is missing, restore it from a copy of the repository (a replica, a versioned bucket or a storage snapshot), then run `pentym check` again.
3. If it cannot be restored, take a new backup of the affected target so a complete snapshot exists, and check the bucket's lifecycle rules and Object Lock settings so it does not happen again.
