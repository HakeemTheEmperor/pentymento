# PTM-7002: object-corrupt

```text
✗ data/4f/4f2a…: pack content does not match its name
→ restore the object from a copy of the repository, or run a new backup; see docs/errors/PTM-7002
```

Other forms name an index file, snapshot, key slot, log segment or replaced private key that does not decrypt or parse, a pack that is too short, a trailer that does not match the index, or chunks that do not match their IDs. `pentym repo rebuild-index` uses this ID for packs whose trailer cannot be read.

## Cause

An object exists but its content is not what pentym wrote: every object is either named by the hash of its content or encrypted with authentication, so any change, truncation or storage fault is detected. Typical causes are disk or storage faults, an interrupted copy, or something other than pentym writing into the repository.

## Impact

Data in the damaged object cannot be used. A damaged pack loses the chunks in it; snapshots that use them cannot be fully restored. A damaged index file only hides chunks that are still in their packs. A damaged log segment shortens the point-in-time recovery window.

## Fix

1. For an index file, run `pentym repo rebuild-index`: the index is rebuilt from the packs.
2. For any other object, restore it from a copy of the repository, then run `pentym check --full`.
3. If it cannot be restored, take a new backup of the affected target, and investigate the storage: run `pentym check --full` regularly to find damage early.
