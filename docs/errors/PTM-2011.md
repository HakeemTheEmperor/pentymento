# PTM-2011: mongodb-standalone

```text
! prod-mg: this is a standalone server with no oplog, so pentym takes snapshots only: no point-in-time recovery
→ run it as a single-node replica set to get point-in-time recovery
```

## Cause

The target is a standalone `mongod`, not a member of a replica set. Only replica set members keep an oplog, the log of changes pentym captures for point-in-time recovery.

## Impact

pentym backs the server up with snapshots only. A restore returns the data as it was at a snapshot; changes since the last snapshot cannot be recovered, and destructive events are not detected.

## Fix

To get point-in-time recovery, run the server as a single-node replica set. This needs a restart and changes no data:

1. Add `replication.replSetName: rs0` to the `mongod` configuration (or start it with `--replSet rs0`) and restart it.
2. In `mongosh`, run `rs.initiate()`.
3. Add `replicaSet=rs0` to the target's `uri`, grant the backup user read on `local` (see [PTM-2009](PTM-2009.md)), and run `pentym doctor <target>`.

If snapshots alone are enough, no change is needed.
