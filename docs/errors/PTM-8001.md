# PTM-8001: capture-lease-held

```text
✗ prod-pg: an agent is capturing this target: its capture lease was renewed while catch-up waited 2m40s
  catch-up runs only when no agent captures, so two never write at once; nothing was stored
→ pentym status prod-pg
```

## Cause

`pentym catch-up` takes a target's capture lease before it stores anything, and only once the lease has expired or was released. An agent renewed the lease while catch-up waited, so an agent is alive and capturing the target.

## Impact

None: the running agent is already capturing, and catch-up stored nothing.

## Fix

Nothing is needed while the agent captures. If you believe no agent is running, look for one on the host named in the lease (`pentym status`), for example a second Kubernetes replica or a service on another machine. After an agent stops, its lease is released at once on a graceful stop, or expires 2 minutes after a crash; run `pentym catch-up` again then.
