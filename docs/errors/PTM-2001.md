# PTM-2001: postgres-connect-failed

```text
✗ prod-pg: cannot connect to Postgres as pentym_backup
  cause: failed to connect to `user=pentym_backup database=postgres`: 10.0.0.5:5432 (db.internal): dial error: connection refused
→ check the host, port, role and password of target prod-pg, then run pentym doctor prod-pg
```

## Cause

pentym could not open a connection to the target's Postgres server. The `cause` line has the driver's reason, such as a refused connection, a timeout, a TLS failure or a rejected password.

## Impact

The operation that needed the connection (a backup, an inventory or a check) did not run. Nothing was changed.

## Fix

- **Connection refused or timeout:** check `host` and `port` in the target's settings, that Postgres is running and listening there (`listen_addresses`), and that no firewall blocks it.
- **Password authentication failed:** check `credentials.backup.user` and that the secret reference in `credentials.backup.password` resolves to that role's password.
- **No pg_hba.conf entry:** allow the role from pentym's host in `pg_hba.conf`, then reload Postgres.
- **TLS errors:** check `sslmode` and the `sslrootcert`, `sslcert` and `sslkey` paths.

Then run `pentym doctor <target>`.
