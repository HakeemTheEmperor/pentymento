# PTM-4007: agent-slot-can-read

```text
✗ the agent's key slot can read backups, and agent.write_only is on
  an agent that can read backups lets anyone who takes over the database host read the backup history
→ set repository.key to an agent slot (pentym key add --agent), or set agent.write_only: false
```

## Cause

`pentym agent` unlocked the repository with a full key slot: one that can unlock the private key and so read every backup. With `agent.write_only: true`, the default, the agent refuses to run with such a slot.

## Impact

The agent did not start; nothing was captured or changed.

The agent runs on or near the database host. If that host is taken over, whatever the agent can unlock is exposed. An agent slot holds only the public key: it can write backups and logs, never read them, so a compromised host cannot read the backup history (PRD 8).

## Fix

Give the agent an agent slot and point `repository.key` at its secret:

```sh
pentym key add --agent --label db-host-1
```

Keep the full slots' passphrases and recovery codes away from the database host, for restores and administration only.

If the agent really must run with a full slot (for example on an admin machine that never touches a database host), set `agent.write_only: false` in its configuration.
