# PTM-6003: restore-object-exists

```text
✗ prod-pg: public.orders still exists in production, so public.orders cannot be restored in place
  nothing was loaded into production; --in-place restores only tables that no longer exist
→ restore without --in-place: it loads the table under a safe name to compare and copy rows from
```

## Cause

`pentym restore --in-place` loads a table under its own name, so it needs the name to be free in production, and the names of the table's indexes and owned sequences too. The table, or one of those names, still exists: the table was truncated or had rows deleted rather than being dropped, or something was created under the same name since.

## Impact

Nothing was loaded into production. The side instance was removed.

## Fix

Run the restore without `--in-place`. The table is then loaded as `<table>_recovered_<date>`, with its indexes and sequences renamed to match, beside the live table; compare the two and copy back the rows you need, for example with `INSERT INTO orders SELECT * FROM orders_recovered_20261122 WHERE …`. If the live table should really be replaced, drop or rename it first, then restore in place.
