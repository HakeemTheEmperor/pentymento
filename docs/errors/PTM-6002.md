# PTM-6002: restore-point-unreachable

```text
✗ prod-pg: cannot restore to 2026-11-21 03:30:00 WAT: it falls in a gap in the captured WAL, between 03:12:40 WAT and 04:00:05 WAT: the replication slot pentym_prod_pg was invalidated (max_slot_wal_keep_size), and the WAL it held was removed
  nothing was restored
→ restore to a point that can be reached: from 2026-11-14 02:00:31 WAT to 2026-11-21 03:12:40 WAT; from 2026-11-21 04:00:05 WAT to 14:02:11 WAT
```

## Cause

A point-in-time restore replays the log from a snapshot taken before the point up to the point. The repository cannot do that for the point asked for, because:

- it is after the newest change pentym has stored, or before the end of the oldest snapshot that has captured log after it;
- it falls in a gap: log that was never stored, because capture was stopped longer than the server kept it ([PTM-5001](PTM-5001.md)), or a stored segment is missing;
- or no snapshot was taken in the stretch of log that covers it.

## Impact

Nothing was restored. Any point in the ranges listed after `→` can be reached.

## Fix

Choose a point inside one of the listed ranges: the latest one before the moment you need, if what you need was written before the gap. `pentym status` shows the window that can be reached now. To make future gaps less likely, see [PTM-5001](PTM-5001.md).
