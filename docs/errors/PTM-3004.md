# PTM-3004: repository-locked

```text
✗ the repository is locked: garbage collection holds the exclusive lock (holder pentym@backup-1, process 4211)
→ retry the backup when prune finishes; scheduled backups retry at their next slot
```

The message names a backup's shared lock instead when prune is the one blocked.

## Cause

Snapshot backups and prune's garbage collection cannot run at the same time: a backup holds a shared lock while it writes, and garbage collection needs the exclusive lock to delete unreferenced packs safely. The operation that arrived second backs off.

## Impact

The blocked operation did not run; nothing was changed. Scheduled runs are skipped and journaled, and run again at their next slot.

## Fix

Wait for the other operation to finish and run the command again. If no backup or prune is actually running, the lock belongs to a crashed process: it stops blocking 30 minutes after its last refresh, and prune removes it.
