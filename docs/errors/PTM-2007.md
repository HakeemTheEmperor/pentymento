# PTM-2007: mongodb-connect-failed

```text
✗ prod-mg: cannot connect to MongoDB as pentym_backup
  cause: server selection error: server selection timeout, current topology: { Type: ReplicaSetNoPrimary, Servers: [{ Addr: db1:27017, Type: Unknown, Last error: dial tcp 10.0.0.6:27017: connect: connection refused }] }
→ check the uri, user and password of target prod-mg, then run pentym doctor prod-mg
```

## Cause

pentym could not connect and log in to the target's MongoDB server. The `cause` line has the driver's reason, such as a refused connection, a timeout, a TLS failure or a rejected login.

## Impact

The operation that needed the connection (a backup, an inventory or a check) did not run. Nothing was changed.

## Fix

- **Connection refused or server selection timeout:** check the hosts and port in the target's `uri`, that `mongod` is running and listening there (`net.bindIp`), and that no firewall blocks it. For a replica set, pentym must reach the members under the names the set's configuration uses, or connect with `directConnection=true` to one member.
- **Authentication failed:** check `credentials.backup.user`, that the secret reference in `credentials.backup.password` resolves to that user's password, and the `authSource` in `uri` (the database the user was created in; `admin` by default).
- **TLS errors:** check `tls=true` and the `tlsCAFile` and `tlsCertificateKeyFile` options in `uri`.

Then run `pentym doctor <target>`.
