# PTM-2004: postgres-role-too-privileged

```text
! prod-pg: pentym_backup is a superuser, which is more privilege than backups need
→ use a role with only REPLICATION: pentym init --print-sql prints one
```

## Cause

The role pentym backs up with is a superuser. Backups work, but they need far less: the `REPLICATION` attribute and read access to the catalogs.

## Impact

None for the backups. But pentym's credentials live on the database host and in its configuration, and a superuser password there can change or destroy any data if it leaks.

## Fix

Create a role with only what backups need, point `credentials.backup` at it, and run `pentym doctor <target>` again:

```sql
CREATE ROLE pentym_backup LOGIN REPLICATION PASSWORD '…';
```

`pentym init --print-sql` prints the complete minimal roles.
