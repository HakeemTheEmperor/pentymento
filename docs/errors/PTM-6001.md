# PTM-6001: no-instance-provider

```text
✗ no instance provider could start postgres 17
  restores and verification need a temporary server of the backup's version
  cause: docker: the Docker daemon is not reachable; local: no postgres 17 binary in tools.postgres or on PATH (found 16)
→ install postgres 17 binaries and list their directory under tools.postgres, or start Docker; then run pentym doctor
```

## Cause

Restores and verification run a temporary database server (a side instance) of the same version as the backup. pentym tries the providers listed in `instance_provider`, in order, and none could start one. The `cause` line gives each provider's reason:

- **docker**: the `docker` command is not on PATH, or the Docker daemon is not running or not reachable by pentym's user.
- **local**: no directory in `tools.postgres` or `tools.mongodb`, or on PATH, holds server binaries of that version. The message lists the versions it did find.

## Impact

The restore or verification did not run. Nothing was changed.

## Fix

Make one provider work, then check with `pentym doctor`:

- Start Docker, or let pentym's user use it. The Docker provider runs the official `postgres:<major>` or `mongo:<version>` image.
- Or install the server binaries of the backup's version and list their directory:

```yaml
tools:
  postgres: [/usr/lib/postgresql/17/bin]
  mongodb: [/opt/mongodb-8.0/bin]
```

Use `instance_provider` to choose the order, for example `[local, docker]` to prefer local binaries.
