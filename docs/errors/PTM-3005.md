# PTM-3005: conditional-create-unsupported

```text
! the storage does not honour conditional create: creating the same object twice succeeded
  locks and capture leases fall back to a weaker protocol; two agents could briefly capture the same target
→ use storage that supports conditional create; see docs/errors/PTM-3005
```

## Cause

`pentym init` tests the storage by creating the same object twice, each time only if it does not exist yet. On storage that supports conditional create, the second attempt fails. Here it succeeded, so the storage ignores the condition.

## Impact

The repository was created and works. Locks and capture leases rely on conditional create so that exactly one process wins a race. Without it they use a fallback that writes a claim, waits 10 seconds and lets the lowest claim win; leases are then best-effort, and in rare timing two agents could capture the same target for a short time.

## Fix

Use storage that supports conditional create: a local directory, or S3-compatible storage that honours `If-None-Match: *` on `PUT`. If you keep this storage, run one agent per target rather than a standby pair.
