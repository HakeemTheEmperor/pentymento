# PTM-3005: conditional-create-unsupported

```text
! the storage does not honour conditional create: creating the same object twice succeeded
  locks and capture leases fall back to a weaker protocol; two agents could briefly capture the same target
→ use storage that supports conditional create; see docs/errors/PTM-3005
```

## Cause

`pentym init` tests the storage by creating the same object twice, each time only if it does not exist yet. On storage that supports conditional create, the second attempt fails. Here it succeeded, so the storage ignores the condition. Some S3-compatible services refuse the condition outright (`501 Not Implemented`); pentym treats that the same way.

`pentym init` records the result in the repository's `config`, so every later command, including agents with write-only credentials, uses the fallback without testing again. `pentym doctor` tests again and warns when the storage no longer matches what was recorded, for example after a repository was copied to different storage.

## Impact

The repository was created and works. Objects that must be created only once are written by checking first, then writing. Locks and capture leases rely on conditional create so that exactly one process wins a race. Without it they use a fallback that writes a claim, waits 10 seconds and lets the lowest claim win; leases are then best-effort, and in rare timing two agents could capture the same target for a short time.

## Fix

Use storage that supports conditional create: a local directory, or S3-compatible storage that honours `If-None-Match: *` on `PUT`. If you keep this storage, run one agent per target rather than a standby pair.
