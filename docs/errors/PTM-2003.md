# PTM-2003: postgres-replication-missing

```text
✗ prod-pg: pentym_backup lacks the REPLICATION attribute, which base backups need
→ ALTER ROLE pentym_backup REPLICATION;
```

The same ID is used when every WAL sender is busy:

```text
✗ prod-pg: all 10 WAL senders are in use (max_wal_senders)
→ raise max_wal_senders and restart Postgres
```

## Cause

Base backups use Postgres's replication protocol. It needs a role with the `REPLICATION` attribute and a free WAL sender: one of `max_wal_senders`, which replicas and other backup tools also use.

## Impact

Base backups fail until this is fixed.

## Fix

- Give the backup role the attribute: `ALTER ROLE pentym_backup REPLICATION;`. It does not need to be a superuser; `pentym init --print-sql` prints a minimal role.
- If the WAL senders are all in use, raise `max_wal_senders` in `postgresql.conf` and restart Postgres. pentym needs one during a backup, and one more for continuous capture.
