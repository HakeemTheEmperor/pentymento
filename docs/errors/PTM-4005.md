# PTM-4005: too-few-key-slots

```text
✗ init needs two full key slots, or one and a paper recovery code; got 1
  with one way to unlock the repository, losing it would make every backup unreadable
→ pentym init --key env:<NAME1> --key env:<NAME2> --agent-key env:<NAME3>, or add --paper
```

## Cause

`pentym init` creates at least two ways to unlock the repository's private key: two full key slots (passphrase or age), or one full slot and a paper recovery code. It was given fewer.

## Impact

No repository was created. Every backup is encrypted, and without a key slot that unlocks, no backup could ever be restored; a second way to unlock protects against losing the first.

## Fix

Give a second full slot or ask for a paper recovery code:

- `--key <reference>` once more, with a different passphrase;
- `--age-recipient age1…` for a slot unlocked by an age identity;
- `--paper`, then write down the printed code and keep it offline.

In a terminal, `pentym init` asks for the passphrases instead.
