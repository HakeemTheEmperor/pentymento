# PTM-2010: mongodb-role-too-privileged

```text
! prod-mg: pentym_backup has root@admin, which is more privilege than backups need
→ use a user with only backup and read on local: pentym init --print-mongo prints one
```

## Cause

The user pentym backs up with has a built-in role that can change data, users or the cluster, such as `root`, `restore`, `readWrite` or `dbOwner`. Backups work, but they only need to read.

## Impact

None for the backups. But pentym's credentials live on the backup host and in its configuration, and a password with write access can change or destroy data if it leaks.

## Fix

Create a user with only what backups need, point `credentials.backup` at it, and run `pentym doctor <target>` again:

```javascript
db.getSiblingDB("admin").createUser({
  user: "pentym_backup",
  pwd: passwordPrompt(),
  roles: [{ role: "backup", db: "admin" }, { role: "read", db: "local" }],
})
```

`pentym init --print-mongo` prints the complete minimal users.
