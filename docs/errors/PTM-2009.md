# PTM-2009: mongodb-privilege-missing

```text
✗ prod-mg: pentym_backup lacks the backup role, which mongodump needs
→ db.getSiblingDB("admin").grantRolesToUser("pentym_backup", [{role: "backup", db: "admin"}])
```

```text
✗ prod-mg: pentym_backup cannot read the oplog (local.oplog.rs), which snapshots of a replica set need
→ db.getSiblingDB("admin").grantRolesToUser("pentym_backup", [{role: "read", db: "local"}])
```

## Cause

The user pentym backs up with cannot read everything a snapshot needs. `mongodump` reads every database, which the built-in `backup` role allows (or a custom role with `find` on every collection). On a replica set it also reads the oplog, which needs read access to the `local` database.

## Impact

pentym does not take the snapshot, because `mongodump` would fail part-way or leave databases out.

## Fix

Grant the missing role with the command shown, as a user that can grant roles, then run `pentym doctor <target>` again. The minimal user for backups has exactly two roles:

```javascript
db.getSiblingDB("admin").createUser({
  user: "pentym_backup",
  pwd: passwordPrompt(),
  roles: [{ role: "backup", db: "admin" }, { role: "read", db: "local" }],
})
```

`pentym init --print-mongo` prints the complete minimal users.
