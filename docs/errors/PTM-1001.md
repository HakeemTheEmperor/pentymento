# PTM-1001: plaintext-secret-rejected

```text
✗ plaintext secret in <file> line <n> (<key>)
  secrets in the config must be references, so the file never holds them
→ replace it with a reference such as env:NAME or file:/path, or set allow_plaintext_secrets: true
```

The same message names an environment variable instead of a file when a `PENTYM_…` override sets a secret to a plain value.

## Cause

A secret field in the config holds the secret itself instead of a reference. pentym only accepts references unless `allow_plaintext_secrets: true` is set, and an environment override of a secret must always be a reference.

## Impact

pentym refuses to load the config, so the command does not run.

## Fix

Replace the value with a reference:

| Reference | Reads the secret from |
| --- | --- |
| `env:NAME` | The environment variable `NAME` |
| `file:/path` | A file, such as a Docker or Kubernetes secret mount |
| `keychain:service/item` | macOS Keychain, Windows Credential Manager or Linux Secret Service |
| `cmd:<helper>` | The output of a helper such as `op read` or `vault kv get` |

If you must keep the value in the file, set `allow_plaintext_secrets: true` and make the file readable only by its owner (see [PTM-1002](PTM-1002.md)).
